# Data Types (資料型別)

## 一句話解釋 (ELI5)
> 資料型別就是告訴資料庫：「這個欄位要存什麼種類的東西？」就像行李箱有分大小，你得選對尺寸才裝得下。

## 生活化比喻 (Analogy)
* 像是表格的**儲存格格式** — Excel 裡你可以設定「數字」、「文字」、「日期」，SQL 也一樣
* 像是**容器的形狀** — 方形盒子裝方形餅乾，圓形桶裝圓形球，選錯容器就裝不進去

## 為什麼重要？ (Why it matters)
* **型別錯誤會導致查詢爆炸：** 如果把年齡存成 TEXT，就無法做 `WHERE age > 18` 的數字比較
* **節省儲存空間：** `BOOLEAN` 只佔 1 byte，但如果用 `TEXT` 存 'true'/'false' 會佔更多空間
* **資料驗證：** 如果欄位是 `INTEGER`，資料庫會自動拒絕你塞入 'abc' 這種文字

## PostgreSQL 常用型別總覽

### 📊 數字類
| 型別 | 範圍 / 說明 | 用途範例 |
|------|-------------|----------|
| `INTEGER` / `INT` | -2,147,483,648 ~ 2,147,483,647 | 年齡、數量、計數 |
| `SERIAL` | 自動遞增 INT（1, 2, 3...） | **主鍵** |
| `BIGINT` | 超大整數 | 超大 ID（如推文編號） |
| `NUMERIC(p,s)` | 精確小數 | 金額（NUMERIC(10,2) = 最多 10 位，小數 2 位） |
| `REAL` / `FLOAT` | 浮點數（不精確） | 科學運算（⚠️ 不適合金額） |

### 📝 文字類
| 型別 | 說明 | 用途範例 |
|------|------|----------|
| `TEXT` | 不限長度文字 | 文章內容、備註 |
| `VARCHAR(n)` | 最多 n 個字元 | 使用者名稱 VARCHAR(50) |
| `CHAR(n)` | 固定 n 個字元（不足補空白） | 國家代碼 CHAR(2) |

### 📅 日期時間類
| 型別 | 格式 | 用途範例 |
|------|------|----------|
| `DATE` | `'2024-02-10'` | 生日、到期日 |
| `TIME` | `'14:30:00'` | 營業時間 |
| `TIMESTAMP` | `'2024-02-10 14:30:00'` | 建立時間、最後修改時間 |

### 🔘 其他
| 型別 | 說明 | 用途範例 |
|------|------|----------|
| `BOOLEAN` | `TRUE` / `FALSE` | 是否完成、是否啟用 |
| `JSON` / `JSONB` | JSON 格式資料 | 設定檔、動態欄位 |
| `UUID` | 通用唯一識別碼 | 分散式系統的主鍵 |

## 選型別的決策流程
```
這個欄位要存什麼？
├── 數字
│   ├── 整數 → INTEGER（或 SERIAL 給主鍵用）
│   └── 小數 → NUMERIC（金額）/ REAL（科學）
├── 文字
│   ├── 長度不確定 → TEXT
│   └── 長度有上限 → VARCHAR(n)
├── 日期/時間 → TIMESTAMP（最通用）
├── 是/否 → BOOLEAN
└── 自動遞增 ID → SERIAL
```
